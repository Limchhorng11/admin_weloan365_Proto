# Settings → User & Role

## Staff ID replaces the standalone referral Code

A staff member's referral code is no longer a separate 5-character field typed in by
hand. Each staff user now has a **Staff ID**, and their referral code is the
**last 5 digits of that ID** — derived, never stored twice, so the two can't drift
apart.

- `StaffUser.code` → `StaffUser.staffId` (still optional: staff whose ID hasn't been
  issued yet simply have no referral code and don't appear in the referral program).
- New `referralCodeFromStaffId(staffId)` helper in `lib/data.ts` is the single source
  of truth for the derivation. Returns `null` when the ID carries fewer than 5 digits.
- **Add user form:** the "Code" field is now **Staff ID** (e.g. `NH-20110247`), and
  the derived code is previewed live beside the input — "Referral code: 10247" — so
  it's obvious where the code comes from. Validation requires 5+ digits.
- **Users table:** shows the staff ID under each name (was the bare code); users
  without one read "No staff ID".
- **Referral Program:** the Credit Officer codes table still lists codes, but now
  derives each from the officer's staff ID and shows that ID alongside the role.
  Subtitle updated to "Each officer's code is the last 5 digits of their staff ID."
- Seed staff IDs were chosen to end in the previously hard-coded codes
  (`NH-20110247` → `10247`, etc.), so existing customer records that reference a
  referring officer's code stay correctly linked.

> **Worth confirming with the business:** because the code is derived, a staff ID
> can't be reassigned without changing that officer's referral code.

**Files touched:** `lib/data.ts`, `components/users-roles-view.tsx`,
`components/settings-modal.tsx`

## Staff users — bulk import from an Excel file

Users gained an **Import** button (next to Add user) that lets an admin bulk-add
staff users from an uploaded `.xlsx` file instead of adding one at a time.

- Upload box accepts `.xlsx`/`.xls`. Expected columns: **Name**, **Email**
  (required), **Staff ID**, **Branch** (optional — Branch falls back to
  "Phnom Penh"). Role is deliberately *not* an import column: every imported user
  lands on the least-privileged non-admin role and is promoted from the Users table
  afterwards.
- After upload, shows a preview table of every parsed row — Name, Staff ID, the
  derived Referral code, Email, Branch — with a per-row status: ready to import, or
  a skip reason (missing name/email, invalid email, staff ID with fewer than 5
  digits, or a duplicate email/staff ID either already in the system or repeated
  within the file).
- Summary counts ("N ready to import" / "N skipped") above the table; only valid
  rows are imported when the admin confirms.
- Imported users get sequential IDs continuing from the current highest, `Active`
  status, and `lastActive: "Just now"` — same convention as adding one manually.

### Implementation notes

- Uses `read-excel-file` (its `web-worker` import path; parsing and validation are
  done manually rather than via the library's `schema` option, for full control over
  per-row error messages). Deliberately **not** the `xlsx` (SheetJS) npm package —
  it has two unpatched high-severity advisories (prototype pollution, ReDoS), which
  is exactly the attack surface a file-upload feature exercises.
- Verified by `tsc`, a production build, and live browser checks of every screen
  touched. **Not** verified end-to-end: this session's sandboxed browser can't script
  a native file-picker selection, so no real spreadsheet was actually uploaded
  through the parser.

**Files touched:** `components/users-roles-view.tsx`, `package.json`,
`package-lock.json`
